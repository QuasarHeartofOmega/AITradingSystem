**Дата:** 2026-11-25

---

## 0. Честная рамка: “гарантированная прибыль” недостижима

Гарантированной прибыли на рынке не существует. Нельзя сделать бота, который обязан зарабатывать при любых рыночных условиях, если стратегия не имеет устойчивого преимущества.

Поэтому цель этого плана формулируется так:

> Довести систему до 10/10 по готовности к реальным деньгам и управляемой прибыльности: бот допускается к Live только при положительном net expectancy после издержек, торгует с ограниченным риском разорения и автоматически останавливается при потере преимущества или деградации инфраструктуры.

Если под “10/10 гарантированной прибыли” понимать обязательство зарабатывать всегда — это недостижимо и не должно быть обещано. Если понимать “максимально надёжная система, которая не торгует реальными деньгами без доказанного преимущества и не разоряется из-за инженерных ошибок” — это достижимая инженерная цель.

## 2. Целевая формула прибыльности

Основная метрика:

```text
net_expectancy = E[net PnL / initial_risk]
```

где `net PnL` учитывает:

- комиссию входа;
- комиссию выхода;
- комиссию в активе, не только в USDT;
- спред;
- проскальзывание;
- частичные филлы;
- dust-остатки;
- задержку исполнения;
- гэп через stop-limit;
- отменённые/неисполненные ордера;
- стоимость простоя капитала.

Live разрешён только если:

```text
net_expectancy > 0
достаточно данных для оценки
оценка устойчива по символам/режимам
риск разорения ограничен
инфраструктура не деградировала
```

Если преимущество не доказано или потеряно — бот должен работать только в Paper/Demo или быть полностью остановленным для новых входов.

# 6. Runtime-гейты для оценки 10/10

| Гейт | Условие | Действие при нарушении |
|---|---|---|
| Equity gate | Equity считается корректно | Запрет новых входов |
| Edge gate | Net expectancy после издержек положительна и достоверна | Запрет Live-входов |
| Calibration gate | Уверенность откалибрована | Запрет Live-входов |
| Regime gate | Рыночный режим подходит стратегии | Запрет входа по символу |
| Liquidity gate | Спред/глубина допустимы | Запрет входа |
| Protection gate | Биржевая защита подтверждена | Аварийное закрытие / запрет новых входов |
| Reconciliation gate | Состояние сверено с биржей | Запрет новых входов до сверки |
| Time gate | Время биржи достоверно | Запрет новых входов |
| Rate-limit gate | Нет банов/критического throttle | Запрет новых входов |
| Drawdown gate | Просадка ниже лимита | Kill-switch / снижение риска |
| Daily-loss gate | Дневной убыток ниже лимита | Kill-switch / остановка |
| Execution gate | Нет серии ошибок исполнения | Пауза / остановка |
| Security gate | Ключи и логи безопасны | Запрет Live |
| Capital gate | Капитал на разрешённой ступени | Снижение ступени / остановка |

# 7. Что считается 10/10 в рамках этого плана

10/10 означает:

```text
Все P0-задачи закрыты.
Все P1-задачи закрыты.
Все P2-задачи закрыты.
Все P3-задачи закрыты.
Все P4-задачи закрыты.
Все P5-задачи закрыты.
Нет критических нарушений инвариантов.
Live разрешён только через runtime-гейты.
При потере преимущества или деградации инфраструктуры бот автоматически ограничивает риск.
```

10/10 **не означает**:

```text
гарантированную прибыль;
обещание доходности;
отсутствие убыточных сделок;
отсутствие просадок;
право торговать без контроля капитала;
право отключать защиту ради статистики.
```

# 8. Запрещённые решения

В рамках этого плана запрещено:

- обещать гарантированную прибыль;
- понижать порог уверенности только ради увеличения числа сделок;
- использовать мартингейл;
- усреднять убыточную позицию без отдельной стратегии;
- считать локальный SL полноценной биржевой защитой;
- считать свободный USDT полноценным equity;
- включать Live одним флагом в общем конфиге;
- логировать секреты, HTTP-тела и полные промпты в Live по умолчанию;
- торговать стейблкоин-пары той же трендовой логикой, что BTC/ETH;
- продолжать Live-торговлю при отрицательном net expectancy;
- продолжать Live-торговлю при деградации данных, времени, rate-limit или защиты;
- сбрасывать kill-switch или дневной лимит после рестарта.

# 10. Итоговая цель

Цель не в том, чтобы бот “больше торговал” или “красивее отвечал”.

Цель:

```text
реальные деньги допускаются только к проверенному преимуществу;
каждый ордер управляем;
каждая позиция защищена;
каждый риск ограничен;
каждая деградация останавливает новый риск;
каждая потеря преимущества переводит систему в безопасный режим.
```

Это и есть практическая версия “10/10 для реальных денег”: не гарантия прибыли, а максимально строгая система, которая не даёт недоказанной стратегии, инженерной ошибке или AI-галлюцинации распоряжаться реальным капиталом без ограничений.
